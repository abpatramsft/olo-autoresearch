THE RESEARCH LOOP

First define better.
Then go find it.

Optimization needs a trustworthy measuring stick. Olo separates building that measurement from changing the code it measures.

01 / EXPLORE/olo-explore

Build the measuring stick.

Understand the repository. Choose a goal with real headroom. Construct or adapt a benchmark and regression gates inside the baseline worktree.

Discover→Check→Approve

YOU GET A checked baseline. Frozen measurement. A clear starting point.

02 / OPTIMIZE/olo-optimize

Change the code. Not the test.

Read failure traces. Explore different hypotheses in isolated worktrees. Measure each candidate against the same benchmark, then review the evidence.

Hypothesize→Measure→Review

YOU GET Reviewed improvements. Useful alternatives. Lessons for the next round.

↳

The last step stays human. Inspect the winning branch. Decide what to merge.

A FEW USEFUL BOUNDARIES

Before you
press enter.

Is this a hosted service?+

No. Olo's controller, worktrees, dashboard, and saved evidence live in your repository on your machine. This website is a static introduction, not the dashboard. Copilot itself uses its configured model services; your benchmarks may also use external services.

Does Olo change my main branch?+

Experiment edits happen in allocated Git worktrees. Benchmark construction belongs in the baseline worktree. A winning experiment stays on its own branch until you explicitly decide to merge it.

How is Olo related to Evo?+

Olo is loosely inspired by Evo and its experiment-driven approach. It is independently written for GitHub Copilot CLI, with a particular focus on checked baselines, binding review, traceable research, and final-test discipline. It is not an Evo plugin, and this is not a feature-parity comparison.

What should I not assume?+

Olo is a local prototype, not a security sandbox or proof of production reliability. Worktrees do not isolate hardware or network access. Independent review is a workflow requirement, not identity authentication. Use representative benchmarks and fresh final questions.
